# 회의록 자동화 — 라이브 시연

녹취록을 `inbox/` 폴더에 넣으면 회의록과 검사 보고가 나오는 과정을 보여 주는 시연 저장소입니다. 사람이 시작을 누르지 않고, 폴더 감시 프로그램이 새 녹취록을 알아보고 Claude Code 를 대화 창 없이 불러 회의록을 쓰게 한 뒤, 검사 셋을 통과한 것만 `minutes/` 에 내놓습니다.

```text
inbox/녹취록.txt → 수집 → 작성(AI) → 검수(검사 셋, 지난 회의록이 있으면 넷) → 전달 → minutes/<회의 이름>/<날짜>_<요청 id>.md · .report.json · .minutes.json
                              ↑ 거부면 다시 (세 번이면 사람에게)
```

## 이 저장소의 지도

| 역할 | 파일 |
|---|---|
| Claude 를 부르는 곳 | `scripts/request.sh` — `claude -p "/handle-request <요청 id>"` 를 부르는 곳은 여기 한 곳(다시 보기에서는 `scripts/replay_claude.py` 가 그 자리를 대신한다) |
| 시작 계기 | `scripts/watch.sh` — `inbox/` 에 녹취록이 생기면 `scripts/request.sh` |
| 지시 | `CLAUDE.md`(프로젝트 지침) · `.claude/commands/handle-request.md`(본 세션) · `.claude/agents/drafter.md`(작성 담당 — 회의록 형식과 규칙) · `graph.yaml` 의 `ask`·`retry_hint`(다시 쓰라는 글) |
| 차단 장치 | `.claude/hooks/` — 등록은 `.claude/settings.json` |
| 막는 규칙 | `policies.yaml` · `.claude/settings.json` 의 `permissions.deny` |
| 흐름 단계 (모델 없음) | `scripts/open_request.py` · `scripts/collect.py`(발화·머리줄·지난 회의록 찾기) · `review.py` 와 `checks/`(M1~M4) · `scripts/deliver.py`(회의 폴더에 회의록) |
| 사람이 치는 것 | `start.sh`(시연 화면 켜기) · `review.py`(검사) |
| 시연 화면 | `app.py` · `web/` |
| 시험 | `tests/` |
| 입력 견본 | `samples/` — 녹취록 둘(A · B), 저장해 둔 초안, `last-week/` 에 A 의 지난주 회의록 A' |

## 시연 화면 켜기

[uv](https://docs.astral.sh/uv/) 가 필요하고, 실제 실행에는 [Claude Code](https://docs.claude.com/en/docs/claude-code) 도 필요합니다. 이 폴더 맨 위에서:

```bash
./start.sh --replay     # 다시 보기 — 모델 없이 저장해 둔 초안으로 (리허설용, 사용량 0)
./start.sh              # 실제 실행 — 올린 녹취록마다 Claude Code 를 부른다
```

`start.sh` 가 가상환경(`.venv`)과 라이브러리를 갖추고, `inbox/` 를 만들고, 시연 화면을 켠 뒤 브라우저로 `http://127.0.0.1:8000` 을 엽니다. 끄려면 Ctrl+C 입니다. `--port 8080` 으로 포트를, `--no-open` 으로 브라우저 열기를 바꿉니다. `scripts/request.sh` 가 `timeout` 명령을 쓰니 리눅스나 WSL 터미널에서 실행합니다.

화면 맨 위는 **결재 라인**입니다. 녹취록 한 장이 서류처럼 inbox 트레이 → 수집 → 작성 → 검수 → 전달 → 회의록 트레이로 움직이고, 검수에서 거부되면 붉은 **반려** 도장이 찍혀 작성으로 되돌아가며, 통과하면 파란 **확인** 도장이 찍힙니다. 세 번 반려되면 "사람에게" 책상으로 갑니다. 같은 녹취록이 또 오면 서류가 inbox 에서 튕겨 나갑니다. 움직임은 꾸밈이 아니라 차단 장치가 요청 폴더에 남기는 기록(`events.jsonl`) 한 줄마다 한 동작이라, 실제 실행에서는 AI 가 쓰는 동안 작성 칸에서 펜이 움직이며 걸린 시간이 올라갑니다. 결재 라인 아래에는 동영상처럼 **이전 · 재생 · 다음** 버튼과 장면 눈금, 지금 장면을 한 줄로 풀어 주는 자막이 있습니다. 기록 한 줄이 한 장면이고, 맨 앞 장면은 커서가 녹취록을 inbox 에 넣는 모습입니다 — 커서는 사람이 손대는 순간(처음 넣을 때, 사람에게 넘어올 때)에만 나옵니다. 끝난 요청은 흐름을 다시 실행하지 않고 장면을 앞뒤로 넘기거나 처음부터 다시 재생할 수 있고(스페이스 · ← · →, 속도 0.5배 · 1배 · 2배), 아래 결재 기록과 결과 서류도 그 장면까지만 보입니다. 주소 끝에 `#scene=9` 처럼 붙이면 그 장면에서 엽니다.

결재 라인에 녹취록 파일을 끌어다 놓거나 견본 버튼을 누르면 파일이 `inbox/` 에 저장됩니다. 흐름을 시작하는 것은 버튼이 아니라 뒤에서 켜진 폴더 감시(`scripts/watch.sh`)입니다. 아래는 세 칸입니다 — 결재 기록(순번이 붙은 기록 줄)과 검사 셋, **원본 녹취록**, 도장이 찍힌 **회의록**. 회의록에 쓴 결정사항의 근거 문장은 원문에서 형광펜과 같은 번호(①②)로 칠해지고, 회의록 쪽 근거에 마우스를 올리면 원문의 그 줄이 같이 표시됩니다. 검수가 "할 일에 담당자가 없다" 로 반려하면 그 할 일이 나온 원문 줄이 붉게 표시됩니다.

| 장면 | 넣는 것 | 화면에 보이는 것 |
|---|---|---|
| 회의록이 나온다 | 견본 "녹취록 A"(기술 블로그 주간 회의, 참석 명단 포함) | 서류가 다섯 칸을 지나 확인 도장을 받고 회의록 트레이로, 오른쪽에 회의록. 원문의 참석 줄에 "정하늘 (발언 없음)" |
| 같은 녹취록이 또 온다 | "녹취록 A" 를 한 번 더 | 서류가 inbox 에서 튕겨 나가고 "건너뛰었습니다" 알림, 요청은 늘지 않는다 |
| 담당자가 없는 할 일 | 견본 "녹취록 B"(결제 서비스 개발 회의 — 결제 실패 원인 확인을 맡은 사람이 없다) | 반려 도장 → 위쪽 붉은 점선으로 작성에 되돌아가기 1/3 → 2/3 → 3/3, 끝에 "사람에게" 책상과 거부 이유 M1 |
| 지난 회의록 | **처음부터**로 비운 뒤 견본 "회의록 A' + 녹취록 A" | 지난주(09-14)에 만들어 둔 회의록 A' 가 회의 폴더에 놓이고, A 가 그 회의록의 열린 할 일 셋을 받아 검사 넷(M4 지난 할 일)을 통과. 원문에 지난 할 일 근거 줄(초록), 회의록에 지난 할 일 표와 "언급 없음 — 확인 필요" |

### 지난 회의록과 참석자 명단 — 녹취록 머리에서 받는다

녹취록 첫 발화 줄 앞의 머리줄 셋을 수집(`scripts/collect.py`)이 읽는다. 셋 다 없어도 흐름은 예전처럼 간다.

```text
회의: 기술 블로그 주간 회의        → 회의 폴더 minutes/기술-블로그-주간-회의/
일시: 2026-09-21(월) 10:00~10:25   → 이 날짜보다 앞선 가장 늦은 회의록을 지난 회의록으로
참석: 김지현, 박도윤, 이서연, 정하늘 → 참석자 명단(말하지 않은 사람도 참석자로, M3 가 대 본다)
```

회의록은 회의마다 폴더가 따로 있고 파일 이름이 날짜로 시작해서, 지난 회의록은 그 폴더 하나의 이름 순서로 찾는다. 다음 회의가 읽는 것은 `<날짜>_<id>.minutes.json` 의 `open_actions`(이번 할 일 + 이번에 언급 없던 지난 할 일)다. 작성 담당은 지난 할 일마다 `carryover` 에 완료·이월·언급 없음과 근거 발화를 쓰고, 검사 M4 가 하나도 빠지지 않았는지와 근거가 녹취에 글자 그대로 있는지를 본다. 언급 없음은 거부하지 않고 보고의 `notes` 와 회의록의 "확인 필요" 로 남긴다. **M4 는 근거 발화가 "완료" 를 뜻하는지 보지 않는다** — 뜻은 사람이 본다. 명단이 초대 명단이면 실제로 왔는지도 모른다.

녹취록 A 는 한 번 처리하면 같은 내용이라 다시 넣어도 건너뛴다. 지난 회의록이 있는 A 를 보려면 **처음부터**로 비우고 "회의록 A' + 녹취록 A" 를 누른다 — 지난주 회의록 A'(`samples/last-week/`)는 지난주에 이미 기록된 것이라 흐름을 다시 지나지 않고 회의 폴더에 그대로 놓인다. 다시 보기는 A 의 견본 초안 둘 가운데 회의 폴더에 지난 회의록이 있는지에 따라 하나를 고른다.

**다시 보기**는 녹화가 아니라 실제 흐름을 한 번 더 실행합니다. 모델이 할 일(초안 쓰기)만 저장해 둔 초안 복사로 바꾸고, Claude Code 가 부르는 차단 장치에는 같은 입력을 넣습니다. 그래서 요청 폴더의 기록과 화면은 실제 실행과 같은 모양으로 쌓이고, 단계 사이를 `REPLAY_DELAY` 초(기본 2) 쉬어 화면이 따라가기 좋게 합니다(예: `REPLAY_DELAY=3 ./start.sh --replay`). 다시 보기에서는 화면이 저절로 따라가지 않습니다 — 녹취록을 넣으면 첫 장면에서 멈추고, 설명하면서 **다음**(→ · PageDown, 발표용 리모컨도 됨)으로 한 장면씩 넘깁니다. 흐름은 뒤에서 계속 돌기 때문에 기록된 장면까지 넘길 수 있고, 넘길 장면이 있으면 다음 버튼이 검게 채워집니다. 저절로 따라가게 하려면 **실제 흐름 따라가기**를 누릅니다. 저장해 둔 초안은 견본 녹취록 둘에만 있어서, 다른 녹취록은 실제 실행에서만 됩니다. 이 서버는 127.0.0.1 에만 열립니다 — 남이 올릴 수 있게 열면 올릴 때마다 이 컴퓨터의 Claude 사용량이 듭니다.

다시 처음부터 하려면 화면 오른쪽 위 **처음부터**를 누릅니다(`requests/` · `minutes/` · `inbox/` 를 비웁니다).

## 모델 없이 확인하기

```bash
uv run python tests/test_flow.py      # 흐름 전체 — 흐름 시험: 통과
uv run python tests/test_app.py       # 시연 화면(다시 보기) — 시연 화면 시험: 통과
bash scripts/request.sh --dry-run samples/transcript-a.txt
```

## 터미널만으로 (화면 없이)

```bash
uv sync && mkdir -p inbox
scripts/watch.sh --interval 5           # 다른 터미널에서: cp samples/transcript-a.txt inbox/
```

Claude Code 가 이 폴더에서 지킬 규칙은 [`CLAUDE.md`](./CLAUDE.md) 에 있습니다.
